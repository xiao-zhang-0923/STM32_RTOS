# uC/OS-II 移植到 STM32F103 全过程

本文记录从 STM32CubeMX 生成 HAL 工程，到 uC/OS-II 在 STM32F103C8T6 上创建并运行 3 个任务的完整过程。
工程最终位置：`D:\Keil5\uCOSII_STM32F103`。

---

## 1. 移植目标与硬件假设

| 项目 | 选择 |
|---|---|
| MCU | STM32F103C8T6，Cortex-M3，64 KB Flash，20 KB RAM |
| 开发板 | 常见 Blue Pill 最小系统板 |
| 晶振 | 8 MHz HSE |
| 系统时钟 | 72 MHz |
| 内核 | uC/OS-II V2.92.11 |
| 编译器 | Keil MDK ARMCC V5.06 update 5 |
| 节拍 | SysTick，1 ms，`OS_TICKS_PER_SEC = 1000` |
| LED1 | PB0，高电平点亮，完整亮灭周期 1 s |
| LED2 | PB1，高电平点亮，完整亮灭周期 3 s |
| 串口 | USART1，PA9=TX，PA10=RX，115200 8N1 |

> 如果你的板子不是 C8T6，而是 C6T6/RC/RB 等，Flash/RAM 大小和启动文件可能不同；
> 本工程按 C8T6（中容量，`STM32F103xB`）配置。

## 2. 先用 CubeMX 建立“能跑裸机”的工程

### 2.1 新建工程

1. 打开 STM32CubeMX，`File -> New Project`。
2. 在 `Part Number` 搜索 `STM32F103C8Tx`，选中 LQFP48 封装，点击 `Start Project`。
3. 如果提示安装 `STM32Cube FW_F1` 固件包，安装 V1.8.7 或更新版本。

### 2.2 配置时钟和调试口

1. `System Core -> RCC`：
   - `High Speed Clock (HSE)` 选择 `Crystal/Ceramic Resonator`。
2. `System Core -> SYS`：
   - `Debug` 选择 `Serial Wire`。
   - `Timebase Source` 保持 `SysTick`。
3. 打开 `Clock Configuration`：
   - `HSE` 输入 8 MHz。
   - `PLL Source` 选择 HSE。
   - `PLL Mul` 选择 `x9`。
   - `SYSCLK` 选择 PLLCLK，目标 72 MHz。
   - `AHB Prescaler` = `/1`，`APB1 Prescaler` = `/2`，`APB2 Prescaler` = `/1`。
   - `Flash Latency` 应为 `2 WS`。
   - 检查：SYSCLK=72 MHz，HCLK=72 MHz，PCLK1=36 MHz，PCLK2=72 MHz。

### 2.3 配置 LED 引脚

在芯片图上左键点击 PB0：

- `GPIO_Output`
- `GPIO Label` 填 `LED1`
- `GPIO mode`：`Output Push Pull`
- `GPIO Pull-up/Pull-down`：`No pull-up and no pull-down`
- `Maximum output speed`：`Low`
- 初始电平：`Low`

PB1 同样配置，标签 `LED2`。

### 2.4 配置 USART1

1. `Connectivity -> USART1 -> Mode` 选择 `Asynchronous`。
2. 参数：
   - Baud Rate：`115200`
   - Word Length：`8 Bits`
   - Parity：`None`
   - Stop Bits：`1`
   - Data Direction：`Receive and Transmit`
   - Over Sampling：`16 Samples`
   - Hardware Flow Control：`None`
3. 引脚自动分配为 PA9=USART1_TX、PA10=USART1_RX。
4. 本实验使用阻塞发送，不需要开 USART 中断。

### 2.5 NVIC 配置

`System Core -> NVIC`：

- `Priority Group`：`4 bits for pre-emption priority`（`NVIC_PRIORITYGROUP_4`）。
- `SysTick interrupt`：优先级 `15`。
- `PendSV`：优先级 `15`。
- 不勾选 USART1 中断。

uC/OS-II 使用 PendSV 做上下文切换，PendSV 必须是最低优先级；SysTick 也放最低，
避免节拍中断打断正在进行的上下文切换。

### 2.6 工程参数

`Project Manager`：

- `Project Name`：`uCOSII_STM32F103`
- `Toolchain / IDE`：`MDK-ARM V5`
- `Application Structure`：`Advanced` 或默认均可
- `Code Generator`：勾选 `Generate peripheral initialization as a pair of .c/.h files`
- `Minimum Heap Size`：`0x200`
- `Minimum Stack Size`：`0x400`

点击 `GENERATE CODE`，得到 `Core/`、`Drivers/`、`MDK-ARM/` 等目录。

> 这时的工程还只是裸机 HAL 工程，没有 uC/OS-II。下一步手工加入内核和移植层。

## 3. 加入 uC/OS-II 源码

### 3.1 源码版本

本工程使用 **uC/OS-II V2.92.11**。原始压缩包来自 Micrium 的
`Micrium_STM3240G-EVAL_OS2.zip`，其中包含：

- `Micrium/Software/uCOS-II/Source/`
- `Micrium/Software/uCOS-II/Ports/ARM-Cortex-M4/Generic/RealView/`

由于 Cortex-M3 与 Cortex-M4 的异常/上下文切换机制相同（M4 额外有 FPU），
本工程以 RealView 移植层为基础，去掉 FPU 相关代码，改成 Cortex-M3 版本。

### 3.2 目录放置

## 4. 配置 `os_cfg.h`

`Middlewares/Third_Party/uC-OS2/Cfg/os_cfg.h` 是本实验最关键的配置文件。
本工程的关键值：

```c
#define OS_LOWEST_PRIO           15u
#define OS_MAX_TASKS              8u
#define OS_TICKS_PER_SEC       1000u
#define OS_TASK_IDLE_STK_SIZE   128u
#define OS_TASK_STAT_EN           0u
#define OS_TMR_EN                 0u
#define OS_DEBUG_EN               0u
#define OS_TASK_SW_HOOK_EN        1u
```

解释：

| 配置 | 作用 |
|---|---|
| `OS_LOWEST_PRIO 15` | 优先级 0～15，数字越小优先级越高；15 留给空闲任务 |
| `OS_MAX_TASKS 8` | 任务控制块池大小；本工程 3 个应用任务 + 空闲任务，8 足够 |
| `OS_TICKS_PER_SEC 1000` | 1 ms 一个节拍，`OSTimeDlyHMSM(0,0,0,500)` 就是 500 ms |
| `OS_TASK_STAT_EN 0` | 关闭统计任务，节省 RAM/Flash；调试时可改 1 |
| `OS_TMR_EN 0` | 不使用软件定时器 |
| `OS_DEBUG_EN 0` | 不编译 `os_dbg.c`，减少代码 |
| `OS_TASK_SW_HOOK_EN 1` | 移植层汇编会调用 `OSTaskSwHook()`，必须保留 |

事件标志、邮箱、内存分区、互斥量、队列、信号量全部设为 0，因为本实验不需要。
如果以后要使用信号量，把 `OS_SEM_EN` 改为 1，并把 `OS_MAX_EVENTS` 设为合适的值。

## 6. 移植层一：`os_cpu.h`

这个文件定义编译器相关的数据类型、临界区方法和栈增长方向。

### 6.1 数据类型

```c
typedef unsigned char  BOOLEAN;
typedef unsigned char  INT8U;
typedef signed   char  INT8S;
typedef unsigned short INT16U;
typedef signed   short INT16S;
typedef unsigned int   INT32U;
typedef signed   int   INT32S;
typedef unsigned int   OS_STK;
typedef unsigned int   OS_CPU_SR;
```

Cortex-M3 是 32 位机，`OS_STK` 为 32 位，栈按 4 字节对齐。

### 6.2 临界区：方法 3

```c
#define OS_CRITICAL_METHOD 3u
#define OS_ENTER_CRITICAL() {cpu_sr = OS_CPU_SR_Save();}
#define OS_EXIT_CRITICAL()  {OS_CPU_SR_Restore(cpu_sr);}
```

`OS_CPU_SR_Save()` 读取 `PRIMASK` 并关中断，`OS_CPU_SR_Restore()` 恢复进入临界区
之前的中断状态。这样在中断里调用内核函数也不会错误地提前开中断。

### 6.3 栈方向与任务切换入口

```c
#define OS_STK_GROWTH 1u
#define OS_TASK_SW()  OSCtxSw()
```

Cortex-M3 的栈从高地址向低地址增长，所以 `OS_STK_GROWTH` 为 1。
`OS_TASK_SW()` 被 uC/OS-II 用来触发一次任务切换，这里指向 `OSCtxSw()`。

## 7. 移植层二：`os_cpu_a.asm`

这是移植的核心。文件实现 6 个函数：

| 函数 | 作用 |
|---|---|
| `OS_CPU_SR_Save` | 保存 PRIMASK，关中断 |
| `OS_CPU_SR_Restore` | 恢复 PRIMASK |
| `OSStartHighRdy` | 启动第一个任务 |
| `OSCtxSw` | 任务级上下文切换入口，挂起 PendSV |
| `OSIntCtxSw` | 中断级上下文切换入口，挂起 PendSV |
| `PendSV_Handler` | 真正的上下文保存/恢复 |

### 7.1 为什么用 PendSV

Cortex-M3 在进入异常时，硬件会自动把 R0～R3、R12、LR、PC、xPSR 压入当前栈。
如果把上下文切换放在 PendSV（最低优先级异常）里，就可以保证：

- 所有中断都处理完，才做任务切换；
- 不会在中断嵌套中间切换任务；
- 任务级和中断级切换可以共用同一段保存/恢复代码。

### 7.2 `OSStartHighRdy`

```asm
OSStartHighRdy
    LDR     R0, =NVIC_SYSPRI14
    LDR     R1, =NVIC_PENDSV_PRI
    STRB    R1, [R0]          ; PendSV 最低优先级

    MOVS    R0, #0
    MSR     PSP, R0           ; PSP=0，告诉 PendSV 这是第一次切换

    LDR     R0, =OS_CPU_ExceptStkBase
    LDR     R1, [R0]
    MSR     MSP, R1           ; MSP 指向专用异常栈

    LDR     R0, =OSRunning
    MOVS    R1, #1
    STRB    R1, [R0]          ; OSRunning = TRUE

    LDR     R0, =NVIC_INT_CTRL
    LDR     R1, =NVIC_PENDSVSET
    STR     R1, [R0]          ; 挂起 PendSV

    CPSIE   I                 ; 开中断，PendSV 立即执行
OSStartHang
    B       OSStartHang
```

第一次切换时 `PSP=0`，PendSV 会跳过“保存旧任务”这一步，直接恢复
`OSTCBHighRdy->OSTCBStkPtr` 指向的新任务栈。

### 7.3 `OSCtxSw` / `OSIntCtxSw`

两个函数都只做一件事：

```asm
LDR R0, =NVIC_INT_CTRL
LDR R1, =NVIC_PENDSVSET
STR R1, [R0]
BX  LR
```

任务级调用 `OSCtxSw()` 后不会立刻切换，而是等 PendSV 被 CPU 响应；
中断级调用 `OSIntCtxSw()` 后，等当前中断退出、所有中断处理完，再进 PendSV。

### 7.4 `PendSV_Handler`

```asm
PendSV_Handler
    CPSID   I
    MRS     R0, PSP
    CBZ     R0, PendSV_Handler_nosave

    SUBS    R0, R0, #0x20
    STM     R0, {R4-R11}          ; 保存 R4-R11

    LDR     R1, =OSTCBCur
    LDR     R1, [R1]
    STR     R0, [R1]              ; OSTCBCur->OSTCBStkPtr = SP

PendSV_Handler_nosave
    PUSH    {R14}
    LDR     R0, =OSTaskSwHook
    BLX     R0
    POP     {R14}

    LDR     R0, =OSPrioCur
    LDR     R1, =OSPrioHighRdy
    LDRB    R2, [R1]
    STRB    R2, [R0]

    LDR     R0, =OSTCBCur
    LDR     R1, =OSTCBHighRdy
    LDR     R2, [R1]
    STR     R2, [R0]

    LDR     R0, [R2]              ; 新任务 SP
    LDM     R0, {R4-R11}          ; 恢复 R4-R11
    ADDS    R0, R0, #0x20
    MSR     PSP, R0

    ORR     LR, LR, #0xF4         ; 异常返回使用 PSP
    CPSIE   I
    BX      LR                    ; 硬件恢复 R0-R3/R12/LR/PC/xPSR
```

### 7.5 向量表名字

启动文件 `startup_stm32f103xb.s` 里的 `PendSV_Handler` 是弱符号。
移植层同时导出：

```asm
EXPORT OS_CPU_PendSVHandler
EXPORT PendSV_Handler
OS_CPU_PendSVHandler
PendSV_Handler
    ...
```

这样链接器会用强符号覆盖启动文件的弱定义，向量表 `0x38` 偏移处直接指向
上下文切换汇编。**不要再在 C 文件里定义 `PendSV_Handler`**，否则会重复定义，
或者把异常返回地址破坏掉。

## 8. 移植层三：`os_cpu_c.c`

### 8.1 专用异常栈

```c
__align(8) OS_STK OS_CPU_ExceptStk[OS_CPU_EXCEPT_STK_SIZE];
OS_STK *OS_CPU_ExceptStkBase;
```

Cortex-M3 在 Handler 模式使用 MSP。任务使用 PSP，中断使用 MSP。
`OSStartHighRdy` 会把 MSP 切到这块 1 KB 的专用栈，避免中断栈和启动文件的主栈
互相干扰。

`OSInitHookBegin()` 会清零这块栈，并把 `OS_CPU_ExceptStkBase` 设为栈顶（8 字节对齐）。
这个 Hook 由 `OSInit()` 自动调用，所以必须在 `OSStart()` 之前完成 `OSInit()`。

### 8.2 任务栈初始化 `OSTaskStkInit`

Cortex-M3 的任务第一次运行时，栈里要伪造一个“异常压栈帧”：

```text
高地址
  xPSR     0x01000000   （Thumb 位）
  PC       task 入口
  LR       OS_TaskReturn
  R12      0x12121212
  R3       0x03030303
  R2       0x02020202
  R1       0x01010101
  R0       p_arg
  R11      0x11111111
  R10      0x10101010
  ...
  R4       0x04040404
低地址  <- OSTCBStkPtr
```

`PendSV_Handler` 先 `LDM` 恢复 R4～R11，再把 PSP 指向 R0，
最后 `BX LR` 触发异常返回，硬件自动恢复 R0～R3、R12、LR、PC、xPSR，任务开始执行。

关键点：

- 栈顶必须 8 字节对齐（Cortex-M3 异常帧要求）。
- xPSR 的 bit 24（Thumb 位）必须为 1，否则会 HardFault。
- LR 初始化为 `OS_TaskReturn`，任务意外返回时不会跑飞。

### 8.3 SysTick 处理

```c
void OS_CPU_SysTickHandler(void)
{
    OSIntEnter();
    OSTimeTick();
    OSIntExit();
}
```

`SysTick_Handler()` 在 `stm32f1xx_it.c` 中：

```c
void SysTick_Handler(void)
{
    HAL_IncTick();
    OS_CPU_SysTickHandler();
}
```

这样 HAL 的 `HAL_GetTick()`/`HAL_Delay()` 仍然可用，同时 uC/OS-II 也得到 1 ms 节拍。

### 8.4 空 Hook

`OSTaskSwHook()` 在汇编里被无条件调用，所以即使不使用应用 Hook，也必须提供空实现。
本工程在 `os_cpu_c.c` 中提供：

```c
void OSTaskSwHook(void)
{
}
```

## 9. 启动顺序：为什么先 `HAL_SuspendTick()`

`HAL_Init()` 会配置并使能 SysTick。如果此时直接 `OSInit()`，SysTick 可能在
内核还没初始化完时进入 `OS_CPU_SysTickHandler()`，造成不可预期的行为。

本工程 `main()` 的顺序：

```c
HAL_Init();
SystemClock_Config();
MX_GPIO_Init();
MX_USART1_UART_Init();
BSP_LED_Init();

HAL_NVIC_SetPriority(PendSV_IRQn, 15, 0);
HAL_NVIC_SetPriority(SysTick_IRQn, 15, 0);

HAL_SuspendTick();       /* 初始化内核期间关闭 tick */

OSInit();
AppTaskCreate();

__disable_irq();
HAL_ResumeTick();        /* 开 tick，但全局中断仍关闭 */
SysTick->VAL = 0;        /* 重新开始一个完整的 1 ms 周期 */
OSStart();               /* OSStartHighRdy 里才会 CPSIE I */
```

这样第一个 SysTick 一定发生在第一个任务已经通过 PendSV 启动之后。

## 12. 常见移植错误

| 现象 | 原因 | 解决 |
|---|---|---|
| `Undefined symbol OSTaskSwHook` | `OS_TASK_SW_HOOK_EN` 为 0，`os_cpu_c.c` 没编译该函数 | 设为 1，或自己提供空函数 |
| `L6200E: Symbol PendSV_Handler multiply defined` | C 文件和汇编都定义了 | 只保留汇编里的强符号 |
| 启动后立刻 HardFault | 任务栈未 8 字节对齐、xPSR 的 Thumb 位为 0、`OS_CPU_ExceptStkBase` 未初始化 | 检查 `OSTaskStkInit` 和 `OSInitHookBegin` |
| 只有空闲任务运行 | 任务优先级/栈大小错误，`OSTaskCreateExt` 返回错误被忽略 | 检查返回值，单步 `AppTaskCreate` |
| LED 不亮 | LED 接反、没有限流电阻、PB0/PB1 没配置为输出 | 用万用表测引脚，检查 GPIO 配置 |
| 串口乱码 | 波特率不对、没有共地、终端编码不是 UTF-8 | 115200 8N1、共地、终端选 UTF-8 |
| 串口无输出 | PA9/PA10 接反 | PA9(TX) 接 USB-TTL 的 RXD |
| 编译报 `OS_CFG.H, Missing ...` | `os_cfg.h` 缺少某个配置项 | 按错误提示补全，或直接使用本工程的 `os_cfg.h` |

更完整的排查见 [05_常见问题.md](05_常见问题.md)。
