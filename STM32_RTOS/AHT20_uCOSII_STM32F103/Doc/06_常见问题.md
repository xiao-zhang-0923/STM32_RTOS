# 常见问题与调试（AHT20 版本）

## 1. 串口一直显示 `AHT20 init: FAIL`

### 1.1 先确认硬件

1. AHT20 的 **VDD** 是否接 3.3 V；
2. GND 是否与开发板共地；
3. PB6 是否接 SCL，PB7 是否接 SDA；
4. 模块是否有 4.7 kΩ 上拉（大多数模块自带）；
5. 杜邦线是否接触良好，是否太长。

### 1.2 用万用表测

断电，用蜂鸣档：

- AHT20 GND 与开发板 GND 应导通；
- AHT20 VDD 与开发板 3.3V 应导通；
- SCL 与 PB6 应导通；
- SDA 与 PB7 应导通；
- 3.3V 与 GND 不应导通（不能短路）。

上电后用万用表测：

- SCL、SDA 对 GND 的静态电压应接近 3.3 V（上拉）；
- 如果一直是 0 V，可能被拉死或接错。

### 1.3 扫描 I2C 地址

本工程地址固定 0x38。可以用 `I2C_Probe(0x70)` 测试：

```c
if (I2C_Probe(AHT20_I2C_ADDR_WRITE))
{
    USART1_SendString("AHT20 ACK at 0x70\r\n");
}
```

如果 `I2C_Probe` 返回 0，说明地址字节没有 ACK，先不要看温湿度，先解决接线/上拉/电源。

---

## 2. `AHT20 trigger NACK at 0x70`

原因：写地址 `0x70` 或命令字节没有收到 ACK。

排查：

1. AHT20 是否上电（3.3V）；
2. SCL/SDA 是否接反；
3. 上拉电阻是否存在；
4. 总线是否被其他设备拉低；
5. 地址是否真的是 0x38（少数兼容模块可能不同，查模块资料）；
6. 软件 I2C 的 SCL 是否真的在翻转（用 Keil 逻辑分析仪或示波器看 PB6）。

---

## 3. `AHT20 read failed (busy/NACK)`

可能原因：

- 触发后等待不足 80 ms；
- 状态字节 BUSY 位（bit7）还是 1；
- 读地址/读时序不对；
- 总线受干扰，CRC 或 ACK 异常；
- 上拉太弱/线太长。

程序在第一次读失败后会再等 20 ms 重试一次。如果仍失败，下一周期重新触发。

---

## 4. `CRC=ERR`

CRC 参数：多项式 0x31，初值 0xFF，校验前 6 字节。

CRC 错误说明数据可能受干扰，但不一定完全不能用。排查：

- SCL/SDA 上拉是否足够（4.7 kΩ）；
- 杜邦线是否过长（建议 <20 cm）；
- 是否有电机、继电器等干扰源；
- 软件 I2C 延时是否被高优先级中断打断太久；
- 尝试把 `I2C_DelayUs(5)` 改成 6～10 µs，降低 SCL 频率（AHT20 没有最低频率要求）。

如果 CRC 偶尔错，可以连续读两次取一致值；如果一直错，先解决硬件。

---

## 5. 串口没有输出

1. USB-TTL 驱动是否安装，设备管理器是否有 COM 口；
2. PA9 是否接 USB-TTL **RXD**，PA10 是否接 **TXD**；
3. GND 是否共地；
4. 波特率 115200、8N1、无校验、无流控；
5. 程序是否运行（LED 是否闪）；
6. 串口助手编码是否 UTF-8（本工程输出有中文启动信息）；
7. 如果只看到启动信息没有温湿度，说明 AHT20 初始化/读取失败，看前面的错误行。

---

## 6. LED 不闪或程序不运行

- 任务一的基础工程是否正常（先烧任务一验证 LED）；
- `OSStart()` 是否执行到；
- SysTick 是否 1 ms；
- 任务栈是否够（AHT20 任务改为 256 OS_STK）；
- HardFault：检查 `PendSV_Handler`、`OS_CPU_ExceptStkBase`、任务栈 8 字节对齐；
- 如果 AHT20 初始化里 `HAL_Delay(40)` 卡住，说明 HAL tick 没起来（SysTick 配置问题）。

---

## 7. `I2C_SIMULATE_ACK` 忘记改回 0

这是仿真专用开关。如果设为 1 后直接下载到实物：

- 程序会以为每个字节都 ACK；
- 读回的数据可能是 0xFF 或乱码；
- 温湿度明显不对，CRC 可能错。

解决：把 `Core/Inc/i2c_soft.h` 中改回：

```c
#define I2C_SIMULATE_ACK    0
```

重新编译下载。

---

## 8. Keil Logic Analyzer 找不到变量

- 确认在 Debug 会话中；
- 确认变量名是 `g_i2c_scl`、`g_i2c_sda`；
- 变量是 `volatile` 全局变量，正常不会被优化掉；
- 如果仍找不到，把优化等级临时改成 `-O0`，Rebuild；
- 确认选择的是 Simulator，不是 ST-Link。

---

## 9. AHT20 地址不是 0x38 怎么办

绝大多数 AHT20 模块固定 7 位地址 0x38。若你的模块资料写的是别的地址：

1. 修改 `aht20.h` 中的：

```c
#define AHT20_I2C_ADDR_7BIT   0x38u
#define AHT20_I2C_ADDR_WRITE  0x70u
#define AHT20_I2C_ADDR_READ   0x71u
```

2. 地址换算规则：

```text
写地址 = 7 位地址 << 1
读地址 = (7 位地址 << 1) | 1
```

3. 用 `I2C_Probe()` 先确认地址能 ACK，再读数据。

---

## 10. 上拉电阻能不能用 STM32 内部上拉

不建议。

- STM32F103 内部上拉约 30～50 kΩ，边沿很慢；
- 100 kHz 下可能还能勉强工作，但长线/多设备时容易出错；
- AHT20 模块通常自带 4.7 kΩ，优先用模块上拉；
- 模块没有上拉时，外接 4.7 kΩ 到 3.3 V。

---

## 11. 软件 I2C 能不能换成硬件 I2C

可以。步骤：

1. CubeMX 把 PB6/PB7 改为 `I2C1_SCL/I2C1_SDA`；
2. 启用 I2C1，100 kHz；
3. 用 `HAL_I2C_Master_Transmit()`/`HAL_I2C_Master_Receive()` 替换 `I2C_Write()`/`I2C_Read()`；
4. AHT20 地址 0x38、命令 `BE 08 00`、`AC 33 00`、读 7 字节都不变。

硬件 I2C 的优点是 CPU 占用低，缺点是调试时不如软件 I2C 直观。
本工程为了逻辑分析仪观察，选择软件 I2C。
